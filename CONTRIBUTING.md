# Как участвовать в MS_KIT

Спасибо, что хотите улучшить ядро и библиотеки ModKit. Проект открыт под лицензией [MIT](LICENSE): вы можете форкнуть репозиторий, менять код и предлагать изменения через Pull Request.

## Быстрый путь
1. Нажмите **Fork** на странице репозитория, клонируйте свой форк.
2. Создайте ветку от `main`: `git checkout -b my-idea`.
3. Внесите изменения, соберите и проверьте (ниже).
4. Отправьте ветку в свой форк и откройте **Pull Request** в `main` исходного репозитория. Заполните шаблон: что изменено, зачем, как проверено.

Крупную идею (новая библиотека, изменение контракта `ModContext`) сначала обсудите в [Issue](https://github.com/Kysnez4/MS_KIT/issues): так вы не потратите время на то, что не впишется в архитектуру.

## Что принимается
- Исправления ошибок в ядре, библиотеках `modkit_*`, модах и документации.
- Новые возможности для авторов модов: расширение библиотек или **новая библиотека**.
- Улучшения документации и примеров (`modkit/docs`, `modkit/melon/examples`).

## Правила для ядра
Ядро (`modkit/melon/ModKit`) — только мод-менеджер: контракт мода, зависимости, хуки, события, реестры, zip-загрузка, окно «Моды», общие UI-примитивы. Всё, что знает устройство игры (враги, заклинания, эффекты, таблицы), — в библиотеки `modkit/melon/mods/modkit_*`. Если идея про игру, а не про менеджер модов, делайте её библиотекой.

- Публичный API ядра меняйте только с обратной совместимостью или с описанием, что ломается и как мигрировать (запись в `modkit/melon/CHANGELOG.md`).
- Библиотека = класс `IKitMod` + `ILibrary<T>`, привязывает хуки и правки к вызывающему моду через `ModContext` (схема — `modkit/docs/MOD_FORMAT.md` §5). Новая библиотека добавляется в `ModKit/Properties.cs` (`InternalsVisibleTo`), если ей нужны внутренности ядра.
- При изменении API обновляйте документацию (`modkit/docs`) и рецепты `modkit/melon/examples/cookbook` (проект должен собираться).
- Версию изменённого мода или библиотеки поднимайте.
- Комментарии в коде — по-русски, стиль как у соседнего кода.

## Сборка и проверка
Нужны .NET SDK 8+ и ссылочные сборки игры (см. [GETTING_STARTED](modkit/docs/GETTING_STARTED.md)).
```bash
dotnet build -c Release modkit/melon/ModKit
python modkit/melon/pack_mod.py <имена>      # библиотеки раньше потребителей
```
Без телефона можно проверить, что всё собирается и zip загружаются (типы разрешаются). Поведение в игре нужно проверять на устройстве ([DEBUGGING.md](modkit/docs/DEBUGGING.md): журнал и `modkit/tools/autotest.py`). **В описании PR честно напишите, что проверено на устройстве, а что только собрано.**

## Чего нельзя добавлять
- Файлы игры (APK, `libil2cpp`, ресурсы), декомпилированный код игры, дампы таблиц и ссылочные сборки (`Assembly-CSharp.dll` и т. п.).
- Ключи, токены, пароли, личные данные.
- Бинарные сборки (`bin/`, `obj/`, `*.dll`, `*.zip`, `*.apk`): релизы публикует владелец.
- Чужие материалы без права на распространение (музыка, картинки).
- Правки сохранений игры без контрольных сумм и всё, что ломает прогресс игрока (подробнее — `modkit/docs/API.md` §9).

## Лицензия
Отправляя изменения, вы соглашаетесь, что они распространяются на условиях лицензии MIT этого репозитория. Игра *Magic Survival*, MelonLoader, Harmony, Il2CppInterop и другие внешние компоненты принадлежат своим авторам и используются на условиях их лицензий; проект неофициальный.

## ИИ-помощники
Использовать ИИ-ассистентов можно; ответственность за изменение несёт тот, кто отправляет PR. Для агентов в репозитории есть памятка [AGENTS.md](AGENTS.md). Укажите в описании PR, если код написан с помощью ИИ.

## Поведение
Будьте вежливы, обсуждайте код, а не людей. Недружелюбные комментарии могут быть удалены.
