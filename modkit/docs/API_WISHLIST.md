# Запросы к API ядра ModKit

Сюда агенты дописывают (в конец, не стирая чужое), что нужно добавить в `melon/ModKit/*.cs`: что, зачем, предлагаемая сигнатура.

## От фаз B1/C1/C2 (active_pack, achievements, kill_streak)

1. **`IEffects.Recalc()`** — запросить у игры пересчёт характеристик героя (то же, что делает игра после подбора артефакта), чтобы только что изменённые `SetGlobalEffects` подействовали сразу. Зачем: подстановка эффектов идёт только внутри `V_Ability_Manager.AbilityStatApply`, поэтому временный бонус (`kill_streak`) без пересчёта попадёт в героя лишь при следующем пересчёте. Сейчас `kill_streak` вызывает `AbilityStatApply(2)` сам (ищет менеджер через `FindObjectsOfType`) — не проверено на устройстве, смысл аргумента `ApplyType` (1 — старт боя, 2 — после выбора?) выведен только из логов. Предложение: `void RecalcStats();` в `ModContext` (ядро знает менеджер: `Effects._mgr`) и вызывать его после `SetGlobalEffects` автоматически, если бой идёт.
2. **Второй ряд кнопок в `ActiveSpellDef`** — поле `Row` (0 — нижний ряд, 1 — выше на 170 px) или произвольные `X`/`Y`. Зачем: сейчас `Slot` сдвигает кнопку только влево на 170 px, при ширине 720 помещается 4 кнопки; `active_pack` из-за этого ограничен 4 заклинаниями. Предложение: `public int Row = 0;` и `y = ScreenH - 520 - Row * 170` в `ActiveSpell.Tick`.
3. **Неблокирующая подпись на экране (`HudLabel`)** — `UiKit.AddHudLabel(name, text, x, y, w, h, size, color)` без `Button`/raycast. Зачем: индикатор серии убийств и тосты достижений сейчас сделаны через `AddHudButton` с пустым обработчиком и перехватывают касания под собой.
4. **Вето в `ChecklistOptions.Set`** — возможность отказаться от переключения галочки (например, `Func<string,bool,bool> TrySet`, результат `false` — галочка остаётся). Зачем: `active_pack` ограничен 4 кнопками и сейчас вместо вето пересоздаёт окно заново (теряется положение прокрутки).
5. **События с данными боя** — в `battleEnd` приложить `victory`/время боя, в `enemyDeath` — `unitId` врага и `isBoss`. Зачем: `achievements` считает время жизни своим таймером (по `InBattle`/`Paused`) и не отличает убийство босса от убийства обычного врага.

## От фазы A (artifact_pack, spell_tuner, class_pack v2)

6. **Чтение файлов из zip мода** — `ctx.ReadAsset(string path) -> byte[]` (файл из архива мода, не с диска телефона). Зачем: `CustomClass.Icon` и `ArtifactDef.IconFile` требуют готовых байт/пути; сейчас у `class_pack` нет иконок классов (на карте классов квадратики), потому что мод не может достать PNG из собственного zip. Заодно картинки для `UiKit.Picture`.
7. **Общий хелпер «окно настроек со страницами и числовыми полями»** — `UiKit.OpenPagedForm(PagedFormOptions)`: страницы (заголовки), строки «подпись + N полей» с `Min/Max/Decimal`, кнопки пресетов сверху, общий `Get/Set`. Зачем: `spell_tuner` собирает это руками из `AddPager` + `AddNumberField` (≈100 строк), то же понадобится `difficulty` и другим экранам настроек.
8. **Скрытые настройки без перечисления в `Options`** — разрешить `ctx.SetSetting(key, ...)` для любого ключа и сохранять его (сейчас значение не переживает перезапуск, если ключ не объявлен в `ModDef.Options`). Зачем: `spell_tuner` вынужден объявлять 64 скрытых `ModOption` (3 числа × 21 заклинание + пресет) в цикле.
9. **Дробные числа в `ModOption`** — проверить/гарантировать шаг 0.1 в `MenuUi` и округление `Math.Round(next * 1000) / 1000` для `Min < 1`. Зачем: у `spell_tuner` множитель урона 0.1–5 (скрытая настройка, поэтому окно «Моды» его не показывает, но тот же `Option` будет нужен модам с видимыми дробными настройками).
