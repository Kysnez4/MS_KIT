## 1. Таблица Class (80 строк, ID 0..79)

Колонки (корейские заголовки) **[П]**:

| Колонка | Смысл |
|---|---|
| `ID` | ID строки (0 — служебная строка-заголовок «Name/Type»). |

| `유형` | тип строки: `학파` (школа, реальный класс) / `실험체` («подопытный», вариант класса) / `` ` `` (пустая заглушка) / `유형` (заголовок). |
| `요구레벨` | 0 у школ; **800** у подопытных (порог открытия/«практики», см. ниже). |

Что описывает что:
- **Название**: `이름`. Иконки в таблице нет — портрет берётся из `Z_Database.SpriteList_ClassPortrait[ID]` **[П]** (массив спрайтов; `data.ts` уже содержит `PORTRAIT_ARRAY.Class = "SpriteList_ClassPortrait"`).
- **Стартовые заклинания**: эффекты `-N`. Пара `(-3,1),(-3,1)` = Дух Lv +2. Журнал подтверждает: при `Game_BattleClassID 1 -> 7` (Призыватель, эффекты `-3,-3`) `Z_Database.List_AllyMagicLevel[3]` стал 2 **[П]**; массив `List_AllyMagicLevel` длиной 46, индекс = ID заклинания.
- **Стартовый уровень героя**: эффект `2` (Ученый, Архимаг: значение 3).
- **Школы/подопытные**: `유형`. Подопытный `41+k` = школа `1+k` (имя совпадает), `Array_ExperimentON[ID-40]` включает его **[П по длинам, Г по индексу]**.
- **Условия открытия**: в таблице только `요구레벨` (800 у подопытных). Сами флаги в сохранении (см. §2).

## 2. Как игра выбирает класс

- **Выбор** хранится в `Z_Database.Game_BattleClassID` (static int, 0x8e0) **[П]**. Журнал: `INIT = 1`, затем в начале боя `SET Game_BattleClassID: 1 -> 7` вместе со всеми `AllyUnitVar_*`, `List_AllyMagicLevel` и т.д. **[П]**. Ровно это поле читает движок эффектов (`melon/ModKit/Effects.cs:226`).
- **Экран главного меню** — `A_MainMenuInformation` (поля: `Obj_FieldClass`, `Obj_ClassSheet(_Inf)`, `List_ObjClassSheet`, `List_ObjClassSheet_Inf` — это `List<GameObject>`, т.е. плитки создаются динамически; `Array_ObjClassObtainSheet` — GameObject[]; `SelectClassID` int 0xa34; `Text_ClassName`, `Text_ClassEffectA`, `Text_ClassEffectB01..04`, `Text_ClassPractice`, `Text_ClassPoint`; `List_ClassObtain`, `List_ClassObtain_Possible`). Методы: `Create_Class()` (RVA 0x102064c, строит плитки), `Select_Class(int)` (0x1021700), `Create_Class_Inf()` (0x1020ce8), `Display_Class()` (0x1022948), `Button_Class_OUT()`, `Play_ClassObtainEffect()`, `ButtonClickEffect_ClassObtain_Confirm()` (покупка/открытие, IAP-поля `Obj_IAP_*ClassObtain*`) **[П]** (имена по дампу).
- **Подопытные**: методы `Button_Experiment(int)`, `Button_Experiment_Select/Sale`, `Play_Experiment()`, поля `Select_ExperimentID`, `Game_ApplyExperimentID` (в журнале 7), `Game_ApplyExperimentNum` (25) **[П]**.
- **Кнопка «выбрать»** — `V_Select_Class.Button_SelectClass()` (0x11381dc), компонент на кнопке **[П]**.
- **Плитка/окно получения**: `X_Sheet_ClassObtain` (`Img_ClassPortrait`, `Text_ClassName`, `ApplyClassID`), `Play_ClassSheetEffect()`.
- **Портреты**: `Z_Database.SpriteList_ClassPortrait` (Sprite[]; размер в журнале не записан — **неизвестен**); `Img_PracticeClassPortrait`/`Img_RewardClassPortrait` в бою (награда практики).
- **Прогресс/открытие** (сохранение): `Array_AbilityClassPractice` (длина 60: [0..23]=46 по школам, [24..57]=0, [58],[59] = золото/самоцветы + контрольная сумма — см. memory «save format»), `Array_ExperimentON` (bool[50], индексы 1..25 = 1: подопытные 41..65), `List_AbilityClassObtain`(`[0]`), `List_AbilityClassSelect`, `List_AllyAbilityClassPossible`, `ApplyAbilityClassNum` (3). Значение 46 в `Array_AbilityClassPractice` у всех 24 школ — «очки практики»; индекс = ID-1 **[Г]**, свободных ячеек 24..57 → до ~34 новых школ без роста массива.
- **Жёсткие лимиты**: не найдены в дампе (поля — списки, а не фиксированные массивы плиток), но код `Create_Class` скрыт (IL2CPP, нужен Ghidra/анализ RVA 0x102064c): цикл может идти по `Dictionary_Class` до пустого имени/фикс. числу 24 **[Г]**. `Array_ObjClassObtainSheet` может оказаться фиксированной длины → проверить `length` на устройстве.

## 3. Что делает мод, чтобы новый класс работал в бою

Образец «добавить запись»: `melon/mods/modkit_data/Artifacts.cs` (`AddArtifact`), `Commands.cs` (`Sprites.Ensure`, `Sprites.GrowInts`, `AddSynergy`).

1. **Строка Class**: переписать свободную заглушку 25..39 (`t.Edit`) или `t.CloneRow(src)` + `MaxId()+1` (будет 80). **Рекомендация: 25..39** — индекс в массивах и ID уже «внутри» таблицы; `Add` по `MaxId()+1` даст 80 и выйдет за 80-строчные массивы (если они есть). Заполнить `이름`, `유형`=`학파`, строки описания (`TextChanges`/`DefaultLines`, как у синергий), пары эффектов (до 9), `효과 설명줄 개수`.
2. **Иконка**: `Sprites.Ensure("SpriteList_ClassPortrait", id, cloneFrom)` — растит массив и копирует спрайт образца (как для артефактов/синергий). Свою PNG: `UiKit.SetSprite/SetImageOverlay` в плитке.
3. **Индексируемые по ID массивы**: по аналогии с `Array_SynergyObtain` (без роста — `IndexOutOfRange` в `Start_Ability`) нужно проверить: `Array_AbilityClassPractice` (хватает: до индекса ~57), `SpriteList_ClassPortrait` (Ensure), `List_ObjClassSheet*` (список плиток; наполняет игра в `Create_Class`), `Array_ObjClassObtainSheet` **[Г]**. Для подопытных — `Array_ExperimentON` (50 → растить через `GrowInts` аналог для bool[], нужен `GrowBools`). Практических ID сверх 24 нет в игре, поэтому каждое индексирование «по ID класса» подозрительно: искать в `Create_Class/Display_Class/Select_Class` (через gamelog `SET`/перехват).
4. **Эффекты в бою**: класс выбирается в `Game_BattleClassID`; `V_Ability_Manager.AbilityStatApply(int)` (RVA 0x1103210) берёт из `Dictionary_Class[ID]` пары `효과ID_NN` и применяет — это гипотеза, но подтверждена косвенно: журнал показывает пересчёт `AllyUnitVar_*` сразу после `SET Game_BattleClassID`, а `Effects.cs` использует класс как источник эффектов **[П косвенно]**. Значит, достаточно, чтобы строка Class[ID] содержала нужные пары. Стартовые заклинания (-N) разбирает другой код (заполняет `List_AllyMagicLevel` при старте боя) — работает для любых N 1..21 и 30..39 **[П по Class 7]**.
5. **Открытие**: для нового класса нужен флаг в сохранении (если игра требует открытия): `Array_AbilityClassPractice[ID-1]`/`List_AbilityClassObtain`. Мод может писать в статические массивы (в сейв они сериализуются; **не трогать** [58],[59] — контрольная сумма, иначе ERROR-экран).

## 4. Минимальный первый эксперимент

Без UI и без новой иконки:
1. `WhenReady` → `t = Table("Class")`; взять образец, напр. 1 (Чародей); `row = t.IndexOf(25, idCol)` (пустая заглушка); скопировать в неё все ячейки строки 1 (`CloneRow` не подходит — вставит новую строку; нужен `Edit(25, всё)`), поменять `이름` на «Тест», `유형`=`학파`, эффекты (напр. 4=50, 6=3, -1 x2).
2. `Sprites.Ensure("SpriteList_ClassPortrait", 25, 1)` — иконка Чародея.
3. Проверить `Array_AbilityClassPractice.Length` ≥ 26 (есть, 60).
4. Подписка: когда игра на экране выбора, не выводя UI, из консоли/кнопки мода записать `Z_Database.Game_BattleClassID = 25` (static int, не Obscured) до старта боя; игра сама применит Class[25].
5. В бою смотреть по `gamelog.txt`: `SET Game_BattleClassID: .. -> 25` (если игра перезапишет при старте — привязаться через `Select_Class(int)`/`Button_SelectClass` после-хуком) и значения `AllyUnitVar_*` (Атака +50%).
Критерий успеха: статы героя изменились, нет вылета на `Start_Ability`. Откат: вернуть ячейки (см. `Edit`/`Edited` в `DataLib.cs`).

Риски:
- **IndexOutOfRange за границами массивов по ID** (как `Array_SynergyObtain`): для ID 25..39 вероятнее всего в границах; для ID ≥ 80 — выход. Исключение IL2CPP = abort и зависание игры (см. комментарий в `Artifacts.cs`) — никогда не допускать чтения за границей.
- `Create_Class` может перечислять плитки по жёстким 24 или по заглушкам по имени «`» — если игра рисует плитку по каждому `유형==학파`, новая школа может показаться в меню без иконки/с битым описанием; сначала проверить без UI-изменений, что меню не падает.
- `SpriteList_ClassPortrait` может быть индексирован и для подопытных (ID 41..65) — размер массива неизвестен; `Ensure` сохраняет прежние элементы, но не пишет в промежуточные индексы (там `null`) — нельзя сносить массив меньше текущего.
- Сохранение: не менять [58],[59] `Array_AbilityClassPractice` и длину массивов, которые сериализуются (лучше не растить сейв-массивы); сетевой anti-cheat — `ObscuredInt` у `Game_ResearchPoint` и др., но `Game_BattleClassID` обычный int.
- Условные/активные эффекты класса (напр. эффект 238 Епископ, ультимейты) через подмену слотов не включаются (docs/CONDITIONAL.md) — только статы.
- Нужно подтвердить: «подопытные» (41..65) читаются отдельно от школ; новый подопытный потребует `Array_ExperimentON`/`Game_ApplyExperimentID`.

## 5. Предлагаемый API (modkit_data)

```csharp
public class ClassDef {
    public string Name;
    public List<Effect> Effects = new();          // до 9 пар; -N = заклинание N +значение уровней (`new Effect(-3, 1)`)
    public List<string> Lines;                    // до 6 строк описания (как у артефактов)
    public int CloneFrom = 1;                     // школа-образец: иконка и колонки
    public int? Icon;                             // ID школы, чей портрет взять
    public string IconFile;                       // свой PNG для плитки (UiKit.SetImageOverlay)
    public int? Id;                               // желаемый ID (по умолчанию первая пустая заглушка 25..39)
}
int AddClass(ClassDef def);                       // строка Class + Sprites.Ensure(SpriteList_ClassPortrait) + проверки массивов; откат undo
void EditClass(int id, ClassChanges changes);     // имя, эффекты, описание
void SelectClass(int id);                         // Game_BattleClassID = id (для теста без UI)
```

- `AddClass` — по образцу `AddSynergy` (`Commands.cs`): найти свободный ID, `Sprites.Ensure`, при необходимости `GrowInts/GrowBools` проверяемых массивов, откат только если строка последняя (иначе вернуть заглушку, т.к. 25..39 — не хвост таблицы: откат = записать обратно прежние значения ячеек).
- **Pager-меню выбора**: `UiKit.AddPager(parent, x, y, w, h, PagerOptions { Pages = имена классов; OnPage = (i, title, container) => { показать портрет (Sprites.Get), 6 строк описания, кнопку «Выбрать» → SelectClass(id) } })`; стрелки `<` `>` листают, подпись «Имя N / M». Вызывать на главном меню (хук `A_MainMenuInformation.Update`/после `Create_Class`), чтобы не зависеть от родных плиток; родное меню оставить как есть.
- Для открытия в сохранении: `UnlockClass(id)` — писать только ячейки `Array_AbilityClassPractice[id-1]` (и `List_AbilityClassObtain`), если проверка покажет, что игра требует открытия.

## 7. Где применяются эффекты класса (разведка 2)

Метод: свой дизассемблер (Python + capstone) по `libil2cpp.so`, RVA из `dump.cs`; ничего не запускалось, код не менялся. Статики Z_Database: `Dictionary_Class` +0x640 (это `List<Dictionary<string,object>>`), `Array_AbilityClassPractice` +0x88 (int[60]), `List_AllyAbilityLearn` +0x758, `List_AllyMagicLevel` +0x760, `Game_BattleClassID` +0x8e0, `Game_ApplyExperimentID` +0x930, `Array_ExperimentON` +0x98. Пометки: **[П]** прочитано в ассемблере, **[В]** вывод/вероятно, **[Г]** догадка.

### 7.1. Главное: почему подстановка `Game_BattleClassID = 25` перед `AbilityStatApply` не работает [П]
1. `V_Ability_Manager.AbilityStatApply(int)` (RVA 0x1103210) **не читает `Game_BattleClassID`** вообще (среди всех чтений статика +0x8e0 его нет). Он обходит **список `Z_Database.List_AllyAbilityLearn`** (статик +0x758; вызов `bl 0x1255c98` на 0x1103578 делает копию списка) и для каждой записи `e` (берётся `abs(e)`) выбирает ветку по диапазону: `>=90001` (0x15f91) — класс, переход на 0x1105a8c; `>=10001` и т. д. — артефакты/синергии/способности (пороги 0x2711, 0x2329, 0x1f41, 0x1b59 на 0x1104bc4..0x1104c00). Строка класса берётся как `Dictionary_Class.get_Item(e - 90000)` (0x1105aa4..0x1105ac8) — **по позиции в списке**, а не по значению колонки ID.
2. В `List_AllyAbilityLearn` запись `90000 + Game_BattleClassID` кладёт **один раз** `V_Ability_Manager.Start_Ability` (RVA 0x1101160): на 0x1101400 `ldr w11,[x8,#0x8e0]`, на 0x1101424 `add w1,w11,#0x15f90` (после `Clear` списка на 0x11013f0), затем `Add`; вторая запись — `90040 + Game_ApplyExperimentID` (0x1101488: `+0x28`, поле +0x930), т.е. эксперимент — это строка Class[40+ID]. Закончив, `Start_Ability` хвостовым переходом вызывает `AbilityStatApply` (0x1102ef4).
3. Значит, к моменту вашего хука в списке уже лежит `90001` (класс 1), и пересчёт берёт строку Class[1], что бы ни лежало в `Game_BattleClassID`. [П]

### 7.2. Все чтения/записи `Game_BattleClassID` (+0x8e0, поиск `ldr/str w?,[x?,#0x8e0]`)
Записи:
- `A_MainMenuInformation.Button_AreaStart` (0x1021268): на 0x10215f0 и 0x10216cc `Game_BattleClassID = this.SelectClassID` (поле +0xa34), затем `Start_Ability` (хвостовой `b 0x1101160` на 0x10216f8). Это тот самый «1 → 7» из gamelog в момент нажатия «Старт», а не отдельный «выбор в бою» [П]. ### 7.3. Как из строки Class берутся эффекты (AbilityStatApply, ветка класса 0x1105a8c..0x1107eb8) [П]
Колонки читаются по порядку таблицы (литералы строк по адресам слотов; порядок сверен с числом 8+9+9+1 чтений): `특수값01..08` → массив x29[1..8]; `효과ID_01..09` → x25[1..9]; `효과ID_NN값` (01..09) → x26[1..9]; затем колонка `유형` (литерал 0x250d280) сравнивается со строкой (0x250d270, `String.op_Equality` на 0x110665c). Дальше:
- **Если `유형` совпала (школа `학파`) и запись положительная** — на 0x1106670..0x1106698 создаются **новые нулевые** массивы x25/x26 и заполняются **только открытые уровнем практики** слоты: `practice = Array_AbilityClassPractice[ID-1]` (индекс проверяется границей длины 60: ID-1 >= 60 даёт IndexOutOfRange):
  - `practice >= 1` — слоты 1, 2, 3 (0x11066c0/0x11066f0);
  - `practice >= 4` — слот 4 (0x1106a10/0x1106a2c);
  - `practice >= 10` — слот 5 (0x1106b60);
  - `practice >= 22` — слот 6 (0x1106cb0/0x1106ccc);
  - слот 7: отдельная «запись мастерства» (см. 7.4), слоты 8 и 9 в ветке школы **не читаются вообще** (остаются 0).
  Значения эффектов обрезаются снизу нулём (`bic w8,w8,w8,asr #31`) и сверху 9999999.
- **Если `유형` не совпала** (подопытный, прочее) — выставленные массивы применяются **как есть, все 9 пар, без практики** (переход 0x1107714 → 0x1107eb8). Подтверждение логикой: подопытные ID 41..65 (индекс ID-1 до 64 > длины 60) обязаны идти этим путём [В].
- Применение — общий цикл 0x1107eb8..0x1108020 по слотам 1..9: пара `(e, v)`; `e <= -1` (до -39) → `List_AllyMagicLevel[-e] += v` (пример: 0x1107f24 читает `List_AllyMagicLevel[0x27]`, добавляет `s11` и записывает; индекс = номер заклинания, так что `(-1,3)` = Магическая пуля +3 уровня) [П]; `e` в диапазоне `0x2d5..0x31f` (после `sub 0x2d5, cmp 0x4a`) → `Array_AbilityEffectVar[e] += v` (0x1107ff4..0x1108014); остальное — таблица переходов (`br x9` на 0x1107f20) для обычных статов (docs/EFFECTS.md) [П по структуре, смысл остальных веток не разбирал]. Пары `(1, 0)` — пустышки.
- Применяется ли «только при достаточном уровне»: да, для школ слот открывается порогом практики из списка {1, 4, 10, 22} (плюс слот 7 при 46). Соответствие слотов школы 1 (`(-1,1),(1,0),(1,0),(-1,1),(158,20),(153,1),(151,20),(1,0),(1,0)`): слоты 1..3 — уровень 1 (практика ≥1: `(-1,1)` Пуля +1), слот 4 `(-1,1)` — практика ≥4, слот 5 `(158,20)` — ≥10, слот 6 `(153,1)` — ≥22, слот 7 `(151,20)` — ≥46 (мастерство, 7.4), 8 и 9 не используются [П для порогов 1/4/10/22 и слотов 1..6; слот 7 — по ключам в 0x11079a0, В].

### 7.4. Мастерство (практика ≥ 46)
`Start_Ability`: цикл `i = 8..31` (24 прохода, 0x11025b0..0x1102670): если `Array_AbilityClassPractice[i-8] >= 46` (0x11025e8), в `List_AllyAbilityLearn` добавляется **отрицательная** запись `-(90001 + k)` (`w20` стартует с 0xFFFEA06F и уменьшается). `AbilityStatApply` берёт `abs`, идёт в ветку класса, а отрицательное значение (`tbnz w8,#31` на 0x1107710 → 0x11079a0) включает «слот мастерства» — по ключам читаются `효과ID_07`/`값07` (+ значения 1..3 и 09) [В по ключам]. Цикл ограничен школами 1..24: для ID 25 запись мастерства **не** создаётся (можно добавить вручную в `List_AllyAbilityLearn` значение `-90025`, [Г]). Это глобальный эффект: пока практика ≥46, бонус мастерства школы действует у любого героя [В, по циклу].
Аналогично на 0x1101bf4 цикл по 24 подопытным: включённые `Array_ExperimentON[i]` (кроме выбранного) добавляют свои пассивки `90040+i`.

### 7.5. «Уровень класса» и серые строки (Select_Class 0x1021700, Display_Class 0x1022948, Create_Class 0x102064c)
- Уровень класса = **накопленные очки практики** `Array_AbilityClassPractice[ID-1]` (у школ 1..24 в сохранении 46 = максимум). Пороги **1, 4, 10, 22, 46** (в `Select_Class` — сравнения 0x1021944 (0x2e), 0x1021984 (0x16), 0x10219c4 (0xa), 0x1021a04 (4), 0x1021a44 (1); в `Create_Class` те же на 0x10209d8..0x1020ab8 — звёздочки/рамка плитки) [П].
- Тексты заполняются прямо из ячеек строки `Dictionary_Class.get_Item(SelectClassID)` (0x1021cb4): `Text_ClassName` (+0x658), `Text_ClassEffectA` (+0x660, строка 1), `Text_ClassEffectB01..B04` (+0x668..+0x680, строки 2..5), `Text_ClassPractice` (+0x688), заливка `Img_ClassPracticeLine_Front.fillAmount` (+0x880). Строка 1 раскрашивается по `practice >= 46` (сравнение на 0x10223b0); строка `B0k` — `X_TextColor.TextColor` (цветная) если практика достигла порога k (1/4/10/22), иначе `X_TextColor.TextColor_AllGrey` (серая) [П по структуре, соответствие порога номеру строки В]. Поэтому у нового класса (практика = 0) все строки серые, а «Уровень» остаётся начальным — **это и есть показанная пользователем картина: слоты не открыты** [П].
- **Отдельных массивов текстов по ID нет**: имя/описание берутся из ячеек строки (колонки `이름`, `설명줄NN 색깔`, `효과 설명줄NN`). `Z_Database.Start_DataBase` (0x11508c0) читает CSV Class **для языка** (`Game_SystemLanguage` +0x8bc, ветки `cmp w19,#9` и т.д., 0x1156074..0x1156394; запись в `Dictionary_Class` на 0x115657c). Новая/клонированная строка показывает ровно то, что записано в её ячейках; корейский текст означает, что в ячейки попал корейский источник (клон со строки/таблицы на корейском, значения по умолчанию мода или `Dictionary_Name/Explain` не используются). Проверить: `Game_SystemLanguage` и значения ячеек строки 25 в логе [Г по причине корейского].
- **Плитки меню — только 24** [П]: `Create_Class` (0x102064c) делает сетку 5×5 со счётчиком плиток `[sp+0x1c]` и проверкой `cmp w8,#0x17; b.gt` на 0x10207c0 — плитки создаются только для ID 1..24; кроме того, плитка кликабельна только если `practice[ID-1] > 0` (0x1020c60 `cmp w22,#0; cset gt` → `Selectable.set_interactable`). `Select_Class` берёт `List_ObjClassSheet.get_Item(SelectClassID-1)` (0x10218d8, 0x1021a5c, 0x1021b30) — для ID 25 это индекс 24 при 24 элементах → ArgumentOutOfRange (исключение IL2CPP). То есть **в штатном меню ID 25 выбрать нельзя**; если мод всё же показывает выбор (своя плитка/подмена `SelectClassID`), он не должен вызывать `Select_Class(25)`.

### 7.6. Индекс по позиции или по значению; жёсткие границы [П]
- Все чтения строки класса — `List<Dictionary>.get_Item(int)` по **позиции** = `ID` (при том что строка 0 присутствует; значение колонки `ID` игра не читает). Нужно, чтобы строка 25 стояла в списке на позиции 25.
- `Array_AbilityClassPractice` индексируется `ID-1` с проверкой границы (длина 60; слоты [58],[59] — контрольная сумма золота/самоцветов, не трогать).
- Жёсткие 24: плитки (`Create_Class`), цикл мастерства (`Start_Ability`, i = 0..23), цикл подопытных (24). Жёсткие ID в бою: 8, 14, 18, 19 (+ диапазон 1..23 в `StartInformation_B`).

### 7.7. Стартовые уровни заклинаний от `-N` [П]
Отдельного кода «при выборе в меню» нет: `-N` обрабатываются в том же цикле `AbilityStatApply` (7.3), прибавляя к `List_AllyMagicLevel[N]` при каждом пересчёте. Меню (`Select_Class`) лишь показывает текст. Старт боя: `Button_AreaStart` → `Start_Ability` (список) → `AbilityStatApply`.

### 7.8. Что делать моду (рекомендации)
Практика + слоты — главные причины: у ID 25 `practice[24] = 0`, поэтому школа-ветка открывает 0 слотов, и подстановка ID перед `AbilityStatApply` вообще не влияет (7.1).
1. **Самый простой и надёжный вариант (запасной):** не вводить новый ID, а переписать ячейки строки реально выбираемого класса (напр. ID 1) на время мода (сохранив оригиналы для отката). Практика у школ 1..24 в сохранении = 46, меню/плитки/текст/живые проверки `Game_BattleClassID` работают штатно, слоты 1..6 открыты (слот 7 — мастерство). Ограничения: эффекты в слотах 7..9 действуют только как мастерство (слоты 8, 9 не читаются у школ); редактировать слоты 1..6.
2. **Новый ID 25 (если нужен):** (а) положить строку на позицию 25 (`유형` оставить `학파`); (б) записать `Array_AbilityClassPractice[24] = 46` (или ≥22: тогда слоты 1..6; индекс 24 попадает в «свободные» ячейки сейва, контрольная сумма [58],[59] от него не зависит [В — в сейве не проверено]); (в) выбрать класс **до `Start_Ability`**: хук/запись `Game_BattleClassID = 25` перед `V_Ability_Manager.Start_Ability` (RVA 0x1101160) (либо после `Button_AreaStart` записать `SelectClassID = 25`; проще — Prefix на `Start_Ability`) — тогда в `List_AllyAbilityLearn` появится 90025, а живые чтения (`Create_Ability`, `StartInformation_B` и т. д.) увидят 25. (Альтернатива без хука на `Start_Ability`: в Prefix `AbilityStatApply` заменить в `List_AllyAbilityLearn` значение `90000+realID` на `90025` — один раз.) Плитки/`Select_Class(25)` в штатном меню не использовать (7.5).
3. **Без практики вообще:** сменить `유형` строки 25 на любое значение, отличное от `학파` (например `실험체`): тогда все 9 пар применятся «как есть» без порогов (7.3, ветка не-школы) — но у такой строки пропадёт школьное оформление; подходит, когда класс выбирается только модом. [В, нужно проверить значение литерала 0x250d270 на устройстве.]
4. Рекомендация по порядку проверки: сначала вариант 1 (строка ID 1), чтобы подтвердить, что эффекты вообще доходят до `AllyUnitVar_*` и `List_AllyMagicLevel`; затем вариант 2.
