# Формат мода и его жизненный цикл

## 1. Состав zip

| Файл | Нужен | Что |
|---|---|---|
| `mod.json` | да | описание мода (ниже) |
| `<main>.dll` | да | библиотека с классом `IKitMod` (имя в поле `main`) |
| `icon.png` | нет | иконка карточки (имя можно задать полем `icon`) |
| `sprites.bundle` | нет | спрайты мода; собирается `pack_mod.py` из папки `sprites/` с PNG, грузится `UiKit.LoadSpriteBundle` (API.md) |
| скриншоты | нет | имена в массиве `screenshots` |
| папки с файлами | нет | читаются из мода через `ctx.ReadAsset("путь/внутри/архива")` |
| доп. DLL | нет | имена в `assemblies`: грузятся до `main` и видны другим модам по имени сборки |

## 2. `mod.json`

Данные из `mod.json` главнее данных в `ModDef`. Комментарии `//` и хвостовые запятые допускаются.

| Поле | Тип | Что |
|---|---|---|
| `id` | строка | уникальный id: латиница, цифры, `_ . -` |
| `name` | строка | название в окне «Моды» |
| `description` | строка | описание карточки |
| `version` | строка | числа через точку, например `1.2.0`; по ней идут обновления |
| `author` | строка | автор |
| `main` | строка | имя DLL, например `my_mod.dll` (по умолчанию `main.dll`) |
| `icon`, `screenshots` | строка, массив | картинки в архиве |
| `depends` | объект | `{"id мода": "версии"}`, жёсткая зависимость |
| `loadAfter` | массив id | мягкий порядок: если эти моды включены, ваш стартует после них |
| `library` | bool | мод-библиотека (см. §5) |
| `options` | массив | настройки, §3 |
| `defaultEnabled` | bool | включён при первой установке |
| `restartRequired` | bool | мод правит данные игры; окно «Моды» покажет плашку о перезапуске |
| `assemblies` | массив | дополнительные DLL из архива |
| `assets` | массив | только для `pack_mod.py`: папки, которые кладутся в zip как есть |
| `spritePpu` | число | только для `pack_mod.py`: пикселей на единицу у спрайтов из `sprites/` (по умолчанию 100) |

### Версии зависимостей
`"*"` — любая; `"1.2"` — не ниже 1.2; `">=1.0 <2.0"` — диапазон; `"=1.5"` — ровно. Операторы: `>= <= > < =`. Версия, которую нельзя сравнить (нет `version` у зависимости), не подходит под любое ограничение, кроме `*`.

## 3. Настройки (`options`)

```json
"options": [ { "key": "every", "label": "Раз в, с", "default": 10, "min": 1, "max": 60, "step": 1, "hidden": false } ]
```
Окно «Моды» показывает кнопки `−`/`+` и поле ввода. Значения числовые (`double`) и сохраняются в `config.json`. В коде: `ctx.Setting("every")`, `ctx.Settings`. Изменение настройки **перезапускает мод** (выключение и включение), чтобы он подхватил значение. `ctx.SetSetting(ключ, значение)` меняет и сохраняет значение **без** перезапуска (для модов со своим экраном; такие настройки помечают `hidden`).

## 4. `ModDef` в коде

```csharp
public ModDef Define() => new ModDef {
    Id = "my_mod", Name = "…", Version = "1.0", Description = "…",
    Depends = { ["modkit_combat"] = ">=1.0" }, LoadAfter = { "other_mod" },
    Options = { new ModOption { Key = "n", Label = "…", Default = 1, Min = 0, Max = 9 } },
    OnEnable = ctx => { },            // главный вход: регистрируйте всё здесь
    OnDisable = ctx => { },           // необязательный дополнительный откат
    OnMainMenu = (ctx, menu) => { },  // главное меню построено: можно добавить свои элементы (menu — A_MainMenuInformation)
    OpenSettings = ctx => { },        // если задан, у включённого мода появляется кнопка «Настройки»
};
```
`OnEnable` вызывается на главном потоке. Исключение в `OnEnable` выключает мод; если набор модов не работал, ядро вернёт набор прошлого запуска.

## 5. Библиотеки

Мод с `"library": true` не показывается в списке, включается сам, когда включён мод, который от него зависит, и выключается, когда зависимых не осталось. Библиотека отдаёт API так:

```csharp
public class MyLib : IKitMod, ILibrary<IMyApi>
{
    public ModDef Define() => new ModDef { Id = "my_lib", Name = "…", Version = "1.0", Library = true, OnEnable = ctx => ctx.Expose(this) };
    IMyApi ILibrary<IMyApi>.For(ModContext ctx) => new MyApi(ctx);    // объект привязан к вызывающему моду
}
```
Потребитель: `var api = ctx.Use<IMyApi>("my_lib");` — один экземпляр на мод, пока он включён. Внутри `MyApi` используйте `ctx.OnCleanup`, `ctx.CleanupList()`, `ctx.Every` — тогда всё откатится при выключении **вызывающего** мода. Типы интерфейсов (`IMyApi`) объявляйте в DLL библиотеки; потребитель ссылается на неё в `csproj` и пишет `depends`.

## 6. Жизненный цикл
1. Загрузчик читает все zip из `UserData/ModKit/mods`. Порядок: библиотеки первыми, зависимости раньше зависимых (по `depends`).
2. Включённые моды запускаются в том же порядке. Недостающая зависимость включается сама; если она не запустилась, причина видна в карточке мода.
3. Выключение: откатываются все хуки, события, таймеры, правки и записи реестров (в обратном порядке), затем выключаются зависимые моды и ненужные библиотеки.
4. Конфликт: два мода не могут вызвать `ctx.Replace` на один метод; второй получает `ModConflictException` и ждёт, пока метод освободится.

## 7. Ошибки и защита
- `ctx.Guard("что", () => …)` ловит исключение и пишет `ОШИБКА [мод] что: …`; 5 ошибок за 10 секунд выключают мод, игра продолжает работать. Оборачивайте им рискованный код (колбэки, таймеры, правки таблиц).
- `ctx.Mark("что делаю")` пишет метку в журнал вылетов: если игра упадёт на нативном вызове, при следующем запуске в `modkit.log` будет видно последнюю метку, а мод, на чьём коде случился сбой, отключится.
- `ctx.Warn(текст)` показывает предупреждение в карточке, `ctx.Error(текст)` — как ошибку с подсчётом.
- Если игра упала раньше, чем прошло ~30 секунд после запуска, ядро откатит набор модов к последнему стабильному.

## 8. Правила хорошего тона
- Поднимайте `version` при каждой правке; зависимости указывайте с минимальной версией (`>=1.0`).
- Не меняйте сохраняемые данные игры (практика, золото, прогресс): у них контрольные суммы, игра сбросит прогресс.
- Ничего не держите между боями: объекты врагов и героя в игре переиспользуются.
- Не публикуйте в моде код и файлы игры. Для релиза — README с установкой и благодарностями.
