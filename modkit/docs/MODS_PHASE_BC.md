# Моды фаз B1, C1, C2: active_pack, achievements, kill_streak

Собраны 2026-10-18, все три версии 1.0 (`mod.json` = `ModDef`). Сборка: `python modkit\melon\pack_mod.py active_pack achievements kill_streak` из `D:\Projects\frida`. Результат — `modkit\melon\mods\<имя>.zip`, залиты в `/sdcard/Download/ModKit/` (ставятся кнопкой «+»).
**Статус всех трёх: собрано (компиляция прошла), на устройстве не запускалось.** Исключение — механика ручного каста Огненного шара (`ISpells.AddActive`), проверенная раньше на `active_demo`.
Нужды ядра (то, что пришлось обойти) — в [API_WISHLIST.md](API_WISHLIST.md).

## Проверка событий ядра (по `Events.cs`)

| Событие | Хук | Данные в `EventData` | Как используется |
|---|---|---|---|
| `enemyDeath` | `C_Battle_EnemyUnit.Unit_Death()` (до метода) | `enemy` (объект `C_Battle_EnemyUnit`) | счётчик убийств; чтение `enemy` не требуется |
| `bossSpawn` | `C_Battle_Manager.Create_UnitEnemyBoss(2 арг.)` (до) | `manager`, `unitId` (int), `count` (int) | босс +1 (или `count`, если 1..10) |
| `battleStart` | `C_Battle_Manager.Start()` (после) | `manager` | начало боя, сброс счётчиков боя |
| `battleEnd` | `C_Battle_Manager.End_Battle()` (до) | `manager` | рекорды боя, сохранение |
| `areaChange` | `C_Battle_Manager.Start_AreaChange()` (после) | `manager` | смена зоны +1 |

Имена совпадают. Данные приходят в виде `EventData` (словарь), читать: `((EventData)e).Get<int>("unitId")`. До этого в логах использовались только `battleStart` и `enemyDeath`; `bossSpawn`, `battleEnd`, `areaChange` на устройстве не проверялись: моды пишут по первым событиям строки с данными (см. «Как проверить»). Неизвестно: сколько раз `enemyDeath` срабатывает на одного врага, что означает `count` у `bossSpawn`, вызывается ли `End_Battle` при смерти героя и при выходе из боя.

## 1. active_pack — ручной каст (фаза B1)

**Что делает.** Для выбранных заклинаний отключает авто-каст и рисует кнопки в бою (справа внизу, в ряд справа налево по 170 px; до 4 кнопок: при ширине 720 больше не помещается, второго ряда в ядре нет). Нажатие делает `Burst` залпов (`ISpells.Cast`), затем перезарядка кнопки по игровому времени. Кнопка видна, только если заклинание получено, идёт бой и нет паузы.

**Какие заклинания.** Из таблицы `Spells.cs` (17 ID) проверено по `dump.cs` (класс `C_Battle_AllyUnit`: есть ли `Is{Имя}_P` и `Play_{Имя}()`):

| ID | Заклинание | флаг `IsX_P` | `Play_X()` | в моде | кнопка | проверено на устройстве |
|---|---|---|---|---|---|---|
| 1 | Магическая пуля | есть | **нет** | нет | — | — |
| 2 | Огненный шар | есть | есть (+Com01/Com03) | да, по умолчанию | Огонь | **да** (active_demo, cast_probe) |
| 5 | Ледяные иглы | есть | есть | да | Лёд | нет |
| 7 | Молния (ThunderA) | есть | есть | да | Гром | нет |
| 8 | Электрозона | есть | **нет** | нет | — | — |
| 9 | Цунами | есть | есть | да | Волна | нет |
| 10 | Метеорит | есть | есть (+Com01/Com03) | да | Метеор | нет |
| 12 | Вихрь | есть | есть (+Com03..05, `TornadoMid_Rotation01`) | да | Вихрь | нет |
| 13 | Электрический удар | есть | есть | да | Удар | нет |
| 14 | Армагеддон | есть | **нет** | нет | — | — |
| 15 | Испепеление | есть | есть | да | Жар | нет |
| 16 | Энергетическая пуля | есть | есть | да | Энергия | нет |
| 17 | Метель | есть | есть | да | Метель | нет |
| 18 | Таинственный луч | есть | есть (много вспомогательных `Play_ArcaneRay*`) | да | Луч | нет |
| 19 | Магический круг | есть | есть (+`EffectA/B`) | да | Круг | нет |
| 20 | Лавовая область | есть | есть | да | Лава | нет |
| 21 | Световая вспышка | есть | есть (+ много вариантов) | да | Свет | нет |

В моде 14 заклинаний; 3 (пуля, электрозона, армагеддон) без `Play_X` — `CanCast` для них false, в список не входят. Сами `CanCast` и пробный `Cast` для каждого заклинания в бою **не запускались** (игра не запускалась), таблица «работает/падает/нет цели» ещё не составлена. Риски: у части заклинаний `Play_X` — не «залп», а бесконечная длительная механика (Таинственный луч, Магический круг, Вихрь, Цунами); два `MoveNext` у них могут дать лишь начальную фазу или ничего; комбо-версии корутин при активных комбинациях `SetAuto` не гасит (ручной и автоматический каст пойдут вместе).

**Настройки.**
- Видимые (окно «Моды»): `cooldown` — перезарядка кнопки, с (по умолчанию 8; 0 — как у заклинания в игре, `UnitApply_{Имя}PSpeed`), `burst` — залпов за нажатие (3).
- «Настройки» → окно-список (`UiKit.OpenChecklist`): «Проверено на устройстве» (Огненный шар) и «Не проверено» (13 остальных). Галочка применяется сразу (кнопки пересоздаются, без перезапуска мода). Пятую галочку мод не принимает (окно открывается заново с пояснением). Выбор хранится в скрытых настройках `s<ID>`.

**Как проверить (`modkit.log`).**
1. После включения: `[active_pack] активных кнопок: 1 [Огненный шар#2], перезарядка 8 с, залпов 3` и `[active_pack] авто-каст Fireball отключён (флаг был …, уровень …)` (последняя строка появляется при входе в бой).
2. В бою с Огненным шаром: кнопка «Огонь» справа внизу; нажатие → `Огненный шар: залпов 3, уровень N, перезарядка игры X с`; авто-каст шаров не идёт (шары летят только по кнопке).
3. Другое заклинание: включить в «Настройках», получить в бою, нажать кнопку. Ожидаемо: строка `<Имя>: залпов N …`. Если вместо неё `каст <Имя> не вышел: …` — нет цели или корутина не годится для ручного каста (запишите, какое).
4. Выключение мода: `авто-каст … возвращён`, кнопки исчезают.

**Не проверено.** Все заклинания, кроме Огненного шара; одновременно 2–4 кнопки; поведение при смене настроек в бою (пересоздание кнопок и возврат/повторное отключение авто-каста); возвращение авто-каста в новом бою.

## 2. achievements — дерево достижений (фаза C1)

**Что делает.** 20 достижений на `PanView` (дерево слева направо; узел открыт, когда выполнено предыдущее; доступный — синий, выполненный — золотой, закрытый — серый). Прогресс по событиям ядра. Тост «Достижение: …» на 4 секунды вверху экрана (`AddHudButton`; пока тост показывается, он перехватывает касания). Награды — постоянные бонусы через `IEffects.SetGlobal`, действуют со следующего пересчёта характеристик игры (со следующего боя; в текущем — после очередного выбора артефакта/уровня).

**Достижения и награды** (счётчик → цель; награда; ID эффекта — из EFFECTS.md):

| Ветка | Достижения (цель) | Награда | Эффект |
|---|---|---|---|
| Убийства (всего) | Первая кровь 1, Сотня 100, Тысяча 1000, Косарь 5000, Жнец 20000 | Атака +1/+1/+2/+3/+5 % | 4 |
| Убийства за бой | Резня 500, Буря клинков 2000 (нужна «Сотня») | Шанс крита +2/+3 % | 14 |
| Бои | Новичок 1, Ветеран 10, Закалённый 50 (нужна «Первая кровь») | Радиус сбора +3/+5/+7 % | 40 |
| Время жизни в бою | 5, 10, 20, 30 минут (нужен «Новичок») | Получаемый урон −1/−2/−3/−4 % | 23 |
| Боссы | Первый босс 1, Охотник 10, Убийца титанов 50 | Макс. здоровье +3/+5/+8 % | 20 |
| Смены зоны | Новые земли 1, Путешественник 5, Покоритель 20 | Скорость передвижения +2/+3/+5 % | 30 |

Суммарно все награды: Атака +12 %, крит +5 %, сбор +15 %, урон −10 %, здоровье +16 %, скорость +10 %. Это 6 разных ID эффектов — движку подстановки нужны столько же свободных слотов (см. «Не проверено»).
Условие дерева: счётчики растут всегда, но достижение засчитывается, когда цель достигнута **и** выполнено предыдущее (проверка повторяется до неподвижной точки, поэтому цепочки закрываются разом).

**Счётчики.** «Убито», «Боссов», «Боёв», «Смен зоны» — суммы за всё время. «Время жизни» — игровое время одного боя (таймер раз в 0,5 с, идёт только при `ISpells.InBattle && !Paused`, то есть не идёт на паузе, в меню и после смерти героя), хранится лучший результат. «Убийства за бой» — лучший результат.

**Хранение.** Файл `UserData/ModKit/achievements.json` (рядом с `config.json`, на телефоне `/sdcard/MelonLoader/com.vkslrzm.Zombim/UserData/ModKit/achievements.json`): счётчики и список `done`. Запись: в конце боя, при получении достижения (по таймеру не чаще раза в 30 с) и при выключении мода. Чтение — при включении (если файла нет, всё с нуля). Чтобы сбросить прогресс — удалить файл при выключенном моде.

**Настройки.** «Награды, % от номинала» (по умолчанию 100; 0 — только счётчики, награды выключены). «Настройки» мода → окно с картой; нажатие на узел — описание, прогресс и награда внизу.

**Как проверить (`modkit.log`).**
- Включение: `прогресс загружен: …` или `файл прогресса не найден …`, `награды: нет`/список, `достижения включены (20)`.
- Первые события: `событие enemyDeath: данные=enemy, тип врага=…` (3 раза), затем `убийств всего 100, за бой 100` (каждые 100), `достижение «Первая кровь» получено … награда: Атака +1%; всего 1 из 20`, `награды: Атака +1% (эффект 4) (масштаб 100%)`.
- Начало боя: `событие battleStart: боёв всего N`. Босс: `событие bossSpawn: unitId=…, count=…; боссов всего N`. Смена зоны: `событие areaChange: смен зоны всего N`. Конец боя: `событие battleEnd: прожито T с, убийств за бой K; рекорды …` и `прогресс сохранён (конец боя): …`.
- Подстановка в игре: `[effects] глобальные эффекты achievements: …`, дальше в бою при пересчёте `[effects] подстановка перед пересчётом: 4=…(глобальный)…`; в `gamelog` — рост `UnitApply_Attack`.
- Файл: `adb shell cat /sdcard/MelonLoader/com.vkslrzm.Zombim/UserData/ModKit/achievements.json`.
- Перезапуск игры: счётчики остаются, `прогресс загружен` показывает те же числа.

**Не проверено.** Всё. В частности: срабатывание `bossSpawn`/`battleEnd`/`areaChange` и смысл `count`; не удваивается ли `enemyDeath` (если убийств «слишком много» — смотреть соотношение с реальными); `battleEnd` при смерти героя; хватает ли свободных слотов эффектов для 6 ID; `AddHudButton`-тост в бою (создаётся из таймера, не из обработчика события); панорамирование карты и `CenterOn` (виджет PanView сам не проверялся — карта классов в class_menu тоже на устройстве не открывалась).

## 3. kill_streak — серия убийств (фаза C2)

**Что делает.** Событие `enemyDeath` увеличивает серию. Серия обрывается, если за `window` секунд игрового времени не было убийств. Каждые `step` убийств серии повышают уровень бонуса (до `maxlevel`): +`atk`% Атаки (эффект 4) и +`speed`% скорости передвижения (эффект 30) за уровень на `duration` секунд с последнего повышения; по истечении бонус снимается (серия продолжается и снова даст бонус на следующем шаге). Всё — на игровом времени: таймер (раз в 0,2 с) идёт, только когда `InBattle` и нет паузы. Индикатор — кнопка слева сверху (x=20, y=280): «Серия N» или «Серия N  ур.L  T.Tс».

**Настройки (по умолчанию).** `step` 10, `window` 4 с, `duration` 8 с, `maxlevel` 5, `atk` 4 %, `speed` 3 %, `recalc` 1. При максимуме: Атака +20 %, скорость +15 %.

**Важное ограничение.** Подстановка эффектов делается внутри `V_Ability_Manager.AbilityStatApply`, поэтому `SetGlobalEffects` сам по себе не меняет героя до ближайшего пересчёта. Мод поэтому после каждой смены бонуса (из таймера, не из обработчика события) вызывает `AbilityStatApply(2)` у менеджера, найденного через `FindObjectsOfType`. Значение аргумента `2` взято из журнала игры (так игра пересчитывает после выбора, `1` — при старте боя); **вызов не проверялся**. Если в игре начнутся сбои, поставьте `recalc` = 0: тогда бонус будет появляться только при пересчётах игры. Предложение — `IEffects.Recalc()` в ядре (API_WISHLIST.md, п. 1).

**Как проверить (`modkit.log`).**
- Включение: `серия убийств включена: шаг 10, окно 4 с, длительность 8 с`.
- Бой: каждые 10 убийств подряд `серия 10 → бонус уровня 1 на 8 с (игровое время …)`, затем `бонус серии: уровень 1, Атака +4%, Скорость +3%`, `[effects] глобальные эффекты kill_streak: 4=4, 30=3`, `пересчёт характеристик выполнен: AbilityStatApply(2)` (или `пересчёт не удался: …`).
- Обрыв/конец: `серия оборвана: N убийств, окно 4 с`, `бонус уровня 1 закончился (серия была N)`, `бонус серии: уровень 0 …`.
- Пауза: во время паузы строки `закончился/оборвана` не появляются, индикатор скрыт; после снятия паузы отсчёт продолжается.
- Прибавка в бою: `gamelog` (`UnitApply_Attack`, скорость) или `[effects] hero.…: старое -> новое (база …)`; цифры в окне характеристик.
- Конец боя: `бой закончен: лучшая серия N`, серия и бонус сбрасываются.
- Выключение: бонус снимается (`глобальные эффекты kill_streak: нет`), индикатор исчезает.

**Не проверено.** Всё: событие `enemyDeath` в реальном бою (скорость срабатывания), `AbilityStatApply(2)` из мода, влияние на производительность пересчёта раз в смену бонуса, совместность с `achievements` и `class_menu` (все три используют `SetGlobalEffects`, значения суммируются по владельцам; ID 4 встречается в двух модах), индикатор-кнопка (`AddHudButton` перехватывает касания).

## Общий чек-лист для пользователя
1. Поставить три zip через «+» (в `Download/ModKit` лежат), включить; перезапуск игры не нужен (ModKit.dll не менялся).
2. `active_pack`: бой с Огненным шаром, нажать кнопку «Огонь»; затем в «Настройках» включить ещё одно (например Молнию), получить в бою и нажать.
3. `achievements`: убить врагов, проверить тост и строки лога, открыть «Настройки» (карта), перезапустить игру и убедиться, что прогресс сохранился.
4. `kill_streak`: убить 10 врагов подряд за 4 с — индикатор и строки лога; затем отключить `recalc`, если игра нестабильна.
5. Пришлите `modkit.log` (и `lastrun.txt`, если был вылет): по нему обновим таблицу проверки заклинаний и разделы «Проверено».
