# ModKit для Magic Survival

Менеджер модов для личного использования. Моды пишутся на **TypeScript**, собираются в один `loader.js` и
исполняются внутри игры через `frida-gadget`. На главном экране над иконкой «Статистика» появляется иконка **гаечного ключа** — она открывает окно «Моды» в стиле энциклопедии:
карточки модов (нажатие включает/выключает), настройки кнопками `−` / `+`, прокрутка пальцем. Состояние сохраняется в `config.json` на телефоне.

## Как это устроено

```
APK игры (патч: libmain.so → libg.so = frida-gadget 16.7.19)
   └─ при старте читает  /sdcard/Android/data/com.vkslrzm.Zombie/files/modkit/loader.js
        ├─ core.ts    реестр модов, включение/выключение, откат, config.json
        ├─ data.ts    чтение/правка игровых таблиц (Z_Database.Dictionary_*)
        ├─ ui.ts      меню MODS на Unity uGUI (строится из A_MainMenuInformation.Update)
        └─ mods/*.ts  ваши моды (подхватываются автоматически)
```

На телефоне рядом с `loader.js` лежат: `config.json` (что включено), `modkit.log` (журнал, смотреть при ошибках).

## Первая установка

Нужно: телефон arm64 с отладкой по USB, Python-venv проекта, Node, Android SDK (`build-tools 36`), JDK.

```powershell
.\modkit\install.ps1        # патч APK + удаление оригинала + установка + заливка loader.js
```

⚠ Оригинальная игра **удаляется** (другая подпись) — локальные сохранения пропадут.

## Ежедневная работа

```powershell
npm run build               # собрать modkit/out/loader.js (проверяет типы)
npm run deploy              # собрать + залить на телефон + перезапустить игру
npm run typecheck           # только проверка типов
```

## Как добавить мод

Встроенный TypeScript-мод одной командой: `npm run add-mod -- путь\к\моду.ts` — копирует его в `modkit/src/mods/`, собирает и заливает на телефон.

Или вручную: создайте файл `modkit/src/mods/<имя>.ts` (имена, начинающиеся с `_`, игнорируются) — больше ничего регистрировать
не нужно, `build.mjs` сам сгенерирует список. Минимальный мод:

```ts
import { defineMod } from "../api";

export default defineMod({
    id: "my_mod",                       // уникальный, латиница
    name: "Мой мод",                    // название в меню
    description: "Что делает.",         // подпись в меню (одна строка)
    options: [                          // необязательно: числовые настройки с кнопками − / +
        { key: "mult", label: "Множитель", default: 2, min: 1, max: 10, step: 1 },
    ],
    onEnable(ctx) {
        // ctx.settings.mult — текущее значение; хуки и таймеры ниже откатываются сами при выключении
    },
});
```

**Ввод числа.** Значение каждой настройки в окне «Моды» — поле ввода: касание открывает цифровую клавиатуру телефона,
число применяется по «Готово» / потере фокуса и обрезается по `min`/`max`. Кнопки − / + работают как раньше. Если `step` и `min`
целые — клавиатура целочисленная, иначе десятичная. Для своих экранов есть `numberField` в `uikit.ts`. Чтобы настройка могла
«выключаться», поставьте `min: 0` и обработайте 0 в моде (так сделан «Артефакт на старте боя»: ID = 0 — ничего не выдавать).

**Плашка «Выйти и применить».** Показывается только для модов с `restartRequired: true` в `defineMod` — это моды, правящие таблицы
данных (`data_*`): их правки полностью работают только после перезапуска. Остальные моды перезапускаются сами при смене настройки,
плашки для них нет.

### Что есть в `ctx`

| Вызов | Что делает |
|---|---|
| `ctx.replace(класс, метод, число_параметров, function(...){})` | Полностью заменяет метод игры. Для вызова оригинала замена не предусмотрена — для «до/после» используйте `before`/`after`. |
| `ctx.after(класс, метод, n, self => …)` / `ctx.before(...)` | Код после/перед методом. `self` — `Il2Cpp.Object` экземпляра; его поля: `self.field<number>("Имя").value`, методы: `self.method("Имя").invoke(...)`. |
| `ctx.every(мс, fn)` | Периодический вызов, пока мод включён (внутри `Il2Cpp.perform`). |
| `ctx.cls("Класс")` / `ctx.cls("Сборка:Класс")` | Класс IL2CPP. По умолчанию сборка `Assembly-CSharp`. |
| `ctx.onCleanup(fn)` | Что сделать при выключении (вернуть значения полей и т. п.). |
| `ctx.settings` | Значения настроек (`options`). |
| `ctx.log(текст)` | Строка в `modkit.log`. |
| `ctx.data.*` | Правка таблиц игры — см. ниже. |

Имена классов, полей и методов смотрите в дампе (`modkit/game.cs` — только `Assembly-CSharp`, `modkit/dump.cs` — всё).
Дамп можно обновить: `npx frida-compile modkit/src/dump.ts -o modkit/out/dump.js -B iife -S`, затем
`.\modkit\push.ps1 modkit\out\dump.js` и забрать `dump.cs` из папки `modkit/` на телефоне.

Готовые примеры: `rune_defence.ts` (хуки + настройки + откат). Примеры кода с `replace`/`after`/`before` см. в `api.ts`
(мод «бессмертие» был одной строкой: `ctx.replace("C_Battle_AllyUnit", "Unit_Damage", 3, function () {})`).

## Моды в формате .zip (без пересборки)

Внешний мод — это **zip-архив**. Внутри обязателен файл **`mod.json`** (META: описание мода) и скрипт; картинки необязательны.

```
my_mod.zip
├── mod.json      META (обязательно)
├── main.js       скрипт с ModKit.define({ onEnable(ctx) {...} })
├── icon.png      иконка в карточке (необязательно)
└── shot1.png     скриншоты, до 3 в карточке (необязательно)
```

`mod.json`:

```json
{
  "id": "my_mod",
  "name": "Название",
  "description": "Что делает мод.",
  "version": "1.0",
  "author": "Автор",
  "main": "main.js",
  "icon": "icon.png",
  "screenshots": ["shot1.png", "shot2.png"],
  "restartRequired": false,
  "defaultEnabled": false,
  "options": [{ "key": "n", "label": "N", "default": 3, "min": 1, "max": 10, "step": 1 }]
}
```

Обязательны только `id` (латиница, цифры, `_ . -`) и `name`. Остальное по умолчанию: `main` = `main.js`, `icon` = `icon.png`.
Значения из `mod.json` главнее тех, что заданы в скрипте. Скрипт — тот же `ModKit.define(...)` и тот же `ctx`, что у TypeScript-модов
(пример — `modkit/examples/wrath_x8/`). Кроме `ModKit.define` скрипту доступны `ModKit.ui` (инструменты `uikit.ts`: кнопки, поля, окна
`openChecklist` / `openNumberForm`) и `ModKit.data` (таблицы игры из `data.ts`, например `new ModKit.data.Table("Synergy")`). Картинки — PNG или JPG.

```powershell
npm run pack-mod -- modkit\examples\wrath_x8        # папка -> wrath_x8.zip (рядом с папкой)
npm run add-mod -- modkit\examples\wrath_x8         # упаковать и залить на телефон (Download/ModKit)
npm run add-mod -- мой_мод.zip                      # залить готовый архив
```

Вручную: скачайте или положите `.zip` в **`Download/`** или **`Download/ModKit/`** (игре выдан «доступ ко всем файлам» —
`install.ps1` делает это командой `appops`). Откройте окно «Моды» и нажмите **«+»** вверху слева: появится список найденных
архивов с `mod.json`; нажатие на строку устанавливает мод (архив копируется в `Android/data/com.vkslrzm.Zombie/files/modkit/mods/`,
оттуда он подключается при каждом старте). Поиск запускается только по «+». Ошибка установки показывается в окне поиска и вверху списка.

Архив можно собрать любой программой (7-Zip, проводник): поддерживаются и «без сжатия», и обычный deflate (распаковывает системный
`libz.so`). Файлы должны лежать в корне архива, а не в подпапке. Ограничения: системного окна «выбор файла» нет (нужен Java-вызов, он
роняет игру); мод с уже существующим `id` повторно не подключается, изменённый архив подхватится после перезапуска игры.
Правка `.zip` заменила прежние одиночные `.js`-моды — они больше не загружаются.

## Правка комбинаций, артефактов, синергий, школ

Это данные, а не код: игра читает CSV в статические таблицы `Z_Database.Dictionary_*`
(`Ability`, `MagicCom`, `Synergy`, `Class`, `AllStat`, `UnitStat`, `BattleUnitEnemy`, `Explain`, `Name`).
Каждая строка — набор колонок с корейскими именами. Описание колонок — [TABLES.md](TABLES.md),
значения ID эффектов — [EFFECTS.md](EFFECTS.md).

* `Ability` — заклинания, пассивки, **артефакты** (`유형 = 아티팩트`, ID 41–222), особые пассивки, исследования.
* `MagicCom` — **комбинации** (65 штук). `Synergy` — **синергии** (101). `Class` — школы и подопытные.
* Эффект записи = до 9 пар (`효과ID_NN`, `효과ID_NN값`). `1` — «пустой» слот. Текст — `효과 설명줄NN` (+ цвет `설명줄NN 색깔`).
  Ссылка на другой эффект в тексте — `##ID##`.

```ts
ctx.data.whenReady(() => {            // таблицы появляются через несколько секунд после старта игры
    // изменить существующую запись (откатится при выключении мода)
    ctx.data.edit("Ability", 41, { "효과ID_01값": 90, "효과 설명줄01": "Атака +90%" });

    // создать новую запись как копию существующей; вернётся новый ID
    const id = ctx.data.add("Ability", 42, {
        "이름": "Мой артефакт",
        "효과ID_01": 4, "효과ID_01값": 100,
        "효과 설명줄01": "Атака +100%",
    });
    ctx.data.addToList("List_ArtifactPossibleGrade_C", id);   // пул выпадения по редкости: C, B, A, P, S
});
```

Пример: `data_wrath_of_heaven.ts` (комбинация «Гнев небес»: число молний ×3 → ×N; текст в энциклопедии меняется, реальное число молний в бою я не проверял). Чтобы увидеть таблицы целиком:
`npm run dump-tables`, залить `modkit\out\dump_tables.js` через `push.ps1`, забрать `tables/*.json` с телефона
(`BattleUnitEnemy` заполняется только в бою — выгружайте во время боя). Потом `python modkit\tools_gen_docs.py`
обновит TABLES.md и EFFECTS.md.

## Изменить характеристики артефакта или комбинации (пошагово)

Да, это можно, и без пересборки. Встроенного редактора значений в окне «Моды» **нет** — правки задаются списком в `.js`-файле.

1. **Найдите запись.** Артефакт — таблица `Ability` (`유형 = 아티팩트`), комбинация — `MagicCom`. ID видны в `modkit/tables/*.json`
   (поле `ID`, имя в `이름`) и в `gamelog.txt` (например, `List_ArtifactObtain: [..,210]` — это ID полученных артефактов,
   `List_ApplyMagicComPossible: [33]` — ID применённой комбинации).
2. **Найдите эффект.** В строке до 9 пар `효과ID_NN` / `효과ID_NN값`. ID эффекта показывает, *что* меняется (4 — «Атака %», 17 — «Урон заклинаний %» и т. д.,
   см. [EFFECTS.md](EFFECTS.md)); значение — *насколько*. Чтобы поменять силу, правьте `...값`. Если у эффекта нет примера в EFFECTS.md,
   смысл определяется опытом: поменяйте значение и посмотрите в `gamelog.txt`, какие поля героя изменились.
3. **Скопируйте шаблон** `modkit/examples/edit_stats.js` в `Download/ModKit/` на телефоне, отредактируйте список `EDITS`
   (таблица, ID, словарь «колонка → значение») и нажмите «+» в окне «Моды». Правки применяются через несколько секунд после старта и
   откатываются при выключении мода.
4. **Поправьте текст.** `효과 설명줄NN` не пересчитывается сам; обновите его, иначе в описании останется старое число.
5. **Проверьте в бою** по `gamelog.txt`: после выбора артефакта в журнале появятся `UnitApply_*` героя и `AllyUnitVar_*` с новыми значениями.

Что нельзя без кода: придумать эффект, которого игра не знает — для этого есть «Свои эффекты» (раздел ниже), и поменять сам алгоритм комбинации.
Значения вроде «×9,99» могут храниться как целое ×100 (у «Аватара» — `효과ID_06값 = 999`), поэтому сверяйтесь с ним на примере.

### Журнал игры (`gamelog`)

Мод «Журнал игры (отладка)» включён по умолчанию и пишет `Android/data/com.vkslrzm.Zombie/files/modkit/gamelog.txt`:
`INIT` — начальные значения, `SET класс.поле: было -> стало` — каждое изменение (`Z_Database`, герой, менеджеры боя и способностей),
`CALLS` — сводка вызовов методов, `OFFER` / `ART` — предложения сундука и торговца с ID артефактов. Забрать файл:
`adb pull /sdcard/Android/data/com.vkslrzm.Zombie/files/modkit/gamelog.txt`. Шумные источники отключаются в начале `modkit/src/mods/gamelog.ts`
(`SKIP_TRACE`, `SKIP_KEY`). Именно по этому журналу удобно понимать, что делает конкретное значение.

Полный справочник по всем артефактам, комбинациям и синергиям (ID, редкость, описание, эффекты) — [CATALOG.md](CATALOG.md); обновляется `python modkit/tools_gen_catalog.py`.

### Пакетные команды и очередь

* `ctx.data.addArtifacts([{...}, {...}])`, `addCombos([...])`, `addSynergies([...])` — несколько записей одним запросом; возвращают массив ID по порядку.
  Для артефактов массив иконок увеличивается один раз, а не на каждый артефакт — это быстрее и безопаснее.
* Правки данных из `ctx.data.whenReady(fn)` ставятся в **очередь** и выполняются на главном потоке после построения главного меню:
  за один заход применяется правка одного мода (раз в ~10 кадров), остальные ждут. Так моды не конкурируют друг с другом
  и не нагружают кадр. Порядок — порядок включения модов.

## Добавить артефакт

Один вызов в `whenReady`. Загрузчик сам делает всё остальное: строку в таблице `Ability`, иконку, пулы выпадения, запись для окна описания и плитку в энциклопедии.

```ts
ctx.data.whenReady(() => {
    ctx.data.addArtifact({
        name: "Клинок бури",
        effects: [[4, 40], [30, 20]],                      // [ID эффекта, значение]; ID — в docs/EFFECTS.md
        lines: ["Атака +40%", "Скорость передвижения +20%"],
        cloneFrom: 42,       // необязательно: образец для иконки и редкости (по умолчанию 42 «Алмаз», класс A)
        weight: 5,           // необязательно: вес выпадения (у обычных 5)
        guaranteed: false,   // тест: выпадает почти всегда
    });
});
```

Готовый пример для внешнего мода без пересборки — `examples/artifact_sword.js`.

Ограничения:
- иконка по умолчанию берётся у образца (`cloneFrom`); своя PNG — через `iconFile`, но только в энциклопедии (см. «Свои иконки артефактов»);
- строка редкости в окне описания у новых артефактов «Артефакт ModKit», а не «Легендарный» и т. д.;
- плитка в энциклопедии появляется при открытии вкладки «Артефакты» и ставится в конец списка;
- описание в бою и в энциклопедии работает; что именно делают эффекты, определяется ID эффекта (смысл части ID известен только по примерам из `EFFECTS.md`);
- при выключении мода плитка остаётся до перезапуска игры, но артефакт перестаёт выпадать.

## Свои эффекты (customEffects)

Эффект — это ID в паре `효과ID_NN` / `효과ID_NN값`; код игры знает только свои ID, неизвестный ничего не делает. Слой `src/effects.ts` позволяет
зарегистрировать обработчик для **своего** ID (`>= 10000`) и использовать его в `effects: [[ID, значение]]` у `addArtifact`, `editArtifact`,
`addCombo`, `editCombo`.

```js
ctx.data.useBuiltinEffects();                       // встроенные 10001..10004 (см. ниже), по желанию
ctx.data.defineEffect({
    id: 10100, name: "Урон огненного шара %",
    apply(hero, value, ctx) {                       // value — число из `효과ID_NN값` строки таблицы
        hero.field("UnitApply_FireballDamage").value *= 1 + value / 100;
    },
});
ctx.data.whenReady(() => ctx.data.addArtifact({ name: "Самоцвет", effects: [[10100, 100]], lines: ["Огненный шар +100%"] }));
```

Как работает: один общий набор хуков (`C_Battle_Manager.Update` и `V_Ability_Manager.AbilityStatApply`, ставятся при первом `defineEffect`, снимаются когда
эффектов не осталось). После пересчёта игрой и раз в ~0,7 с движок читает `Z_Database.List_ArtifactObtain` (артефакты героя) и
`V_Ability_Manager.List_ApplyMagicComPossible` (применённые комбинации), ищет в строках `Ability` / `MagicCom` зарегистрированные ID (пустые слоты 0 и 1 и
незнакомые ID пропускаются) и вызывает `apply` — по разу на каждый артефакт/комбинацию (два источника одного эффекта складываются как два вызова).

Защита от накопления: `hero.field(имя).value` отдаёт **базу** (значение, посчитанное игрой), обработчик пишет цель (`*=`, `+=`), а в игру записывает движок
после всех обработчиков. Если игра пересчитала поле, значение отличается от записанного нами — берётся новая база; поля, которых эффекты больше не касаются
(артефакт потерян, мод выключен), возвращаются к базе. `hero.db("AllyUnitVar_...")` — то же для статических переменных `Z_Database`; `hero.mulPercent(поле, %)`,
`hero.add(поле, n)`, `hero.raw` — объект героя. Целочисленные поля округляются сами.

Встроенные (`useBuiltinEffects`): **10001** урон магической пули +% (`UnitApply_MagicBulletDamage`); **10002** перезарядка заклинаний −%
(`UnitApply_MagicCooltimeRatio`, множитель времени); **10003** +N снарядов магической пули и молний (`UnitApply_MagicBulletNum`, `UnitApply_ThunderNum`);
**10004** радиус сбора +% (`AllyUnitVar_ItemObtainAreaU` и кеш `UnitApply_ItemObtainArea`). Любое другое поле из `modkit/game.cs` (`UnitApply_*`) — свой `defineEffect` на 3 строки.
Пример: `examples/custom_effect_demo.js`.

**Эффекты игры через игру (`expand` и `ctx.data.setEffects`).** Эффект с `expand(value) => [[ID игры, значение], ...]` и глобальные эффекты мода
(`ctx.data.setEffects([[16, 5], [6, -2]])`) не правят поля героя сами: перед каждым `AbilityStatApply` движок временно подставляет эти пары в колонки
`효과ID_NN` строк-источников (класс, синергии, комбинации, артефакты, изученные исследования; для лишних пар берутся свободные слоты с ID 0/1),
игра считает их своим кодом, после вызова колонки возвращаются. Источники героя: артефакты, класс (`Game_BattleClassID`), комбинации, синергии
(`List_ApplySynergyON[ID]`). Мод «Проклятия и дары» работает именно так. Результат точный: игра сама выводит все поля героя.
Проверено в бою на «Проклятиях и дарах»: значения `AllyUnitVar_*` совпали с расчётными, отрицательные значения игра принимает.
Не проверено на устройстве: совпадает ли индекс `List_ApplySynergyON` с ID синергии и берётся ли класс из `Game_BattleClassID` в бою — смотрите строки
`[effects] подстановка` и `включённые синергии` в `modkit.log`.

**Область действия.** Подмена слотов (`setEffects`, `expand`) покрывает **характеристики**. Условные, событийные и активные эффекты игры (убийства, перезарядки, руны) так не включаются: игра обрабатывает их только у артефактов в `List_ArtifactObtain`. Свои условные эффекты делаются отдельными способами (метод игры по своему условию; `AllyUnitVar_*` + поля героя) — см. [CONDITIONAL.md](CONDITIONAL.md), примеры: моды `huntertest` и `rune_defence`. Те же правила у обычных артефактов: при получении ID попадает в `Z_Database.List_ArtifactObtain`, игра зовёт `AbilityStatApply`; значения, записанные в `AllyUnitVar_*` до пересчёта, теряются — писать нужно после него.

Ограничения: текст описания (`lines`) пишете сами; встроенные эффекты регистрирует тот мод, который вызвал `useBuiltinEffects` первым (если его выключить, они пропадут у всех);
ID `< 10000` отвергаются. Не проверено в бою: что игра спокойно относится к ID `>= 10000` в таблице (если где-то индексирует массив по ID эффекта — возможен сбой),
и реальное действие полей на геймплей — смотрите `modkit.log` (строки `[effects]`) и `gamelog.txt` (`SET hero.UnitApply_...`).

⚠ Мод `gamelog` снимает состояние каждые 100–150 мс и сам вызывает заметные тормоза в бою. Держите его выключенным, когда не снимаете данные.

## Свои иконки артефактов (итог разведки, мод `spritetest`)

Измерено на телефоне (`modkit.log`, строки `[spritetest]`):

* **Иконка — область общего атласа.** `Ability41Portrait … Ability222Portrait` (248x288, `packed=true`) лежат в атласах `sactx-N-2048x2048-ETC2-SpriteAtlas_Ability-…`
  (разные артефакты — в разных атласах: `sactx-8`, `-4`, `-6`, `-9`, `-10`, `-5`); комбинации (512x512) и синергии (128x128) — в тех же атласах.
  Атласы **сжаты ETC2_RGBA8 и нечитаемы** (`isReadable=false`). `Sprite.rect` у упакованных спрайтов показывает `0,0 W×H`, реальное положение в атласе из скрипта не видно.
* **Подмена пикселей в атласе невозможна**: `Texture2D.SetPixels/Apply` по правилам Unity на нечитаемой текстуре бросает исключение (на самой текстуре атласа я этого не запускал, чтобы не портить игру), `Graphics.CopyTexture/Blit` в игре вырезаны
  (в дампе у `Graphics` остались только `SetRenderTarget*`), `Sprite.Create` вырезан. Даже если бы запись удалась, спрайт клона — тот же объект/область, что у образца: правка испортила бы иконку образца,
  а для нового ID отдельной области в атласе нет.
* **Работает**: отдельная `Texture2D` из PNG — `File.readAllBytes` (frida) → `byte[]` → `ImageConversion.LoadImage(tex, bytes)` (в логе: `LoadImage -> true, 64x64 format=ARGB32`, пиксели читаются верно).
  `UnityWebRequestTexture` не нужен (асинхронность не требуется). Текстуру показывает `RawImage` — как в иконке «гаечного ключа».
* Поэтому в `addArtifact` есть поле **`iconFile`** (путь к PNG на телефоне, лучше 248x288 с прозрачностью, например `/sdcard/Download/ModKit/blade.png` — читается благодаря `MANAGE_EXTERNAL_STORAGE`).
  Загрузчик кладёт поверх `UI.Image` дочерний `RawImage` (на весь размер Image, `raycastTarget=false`), а сам спрайт делает прозрачным.
  Реализовано **только для энциклопедии**: плитка артефакта (`X_Select_ArtifactShow.Img_ArtifactPortrait`) и окно описания (`V_ArtifactShow.Img_ArtifactDetail_Portrait`;
  общий Image игры — наш RawImage убирается каждый кадр, как только открыт другой артефакт).
  Проверено по логу: плитка создана, `RawImage` 64x64 с rect 248x288 (совпадает с Image), `Image.alpha=0`. **Как это выглядит на экране — не проверено** (скриншоты не смотрел): включите мод
  «Тест иконки (отладка)» (на телефоне должен лежать `…/files/modkit/test.png`), откройте Энциклопедия → Артефакты, в конце списка найдите «Тест иконки» — на плитке и в окне описания должен быть цветной градиент вместо иконки «Алмаза».
* **Не реализовано**: бой (окно выбора `V_Artifact_Manager.Img_ArtifactObtain_Portrait`, торговец `Img_Merchant_Portrait`, листы выбора, список полученных). Там Image создаются игрой и заполняются
  внутри её кода; чтобы подставить RawImage, нужно ловить каждое место (хук на методы заполнения + проверка ID > 222 + создание RawImage рядом с Image). Это технически тем же приёмом выполнимо, но не сделано и не проверено.
  Там остаётся иконка образца (`cloneFrom`/`icon`).
* Для комбинаций и синергий (`addCombo`/`addSynergy`) `iconFile` не добавлен: тот же механизм, но места показа не исследованы.
* Риски: текстура создаётся на главном потоке при первом показе (позже кэшируется; после смены сцены перезагружается, если уничтожена); RawImage не участвует в «клонировании» плиток игрой — если игра пересоздаст плитки, наш overlay
  появится снова только при следующем открытии книги. Вызов `Button_BookArtifact` из своего хука не срабатывает на хуки загрузчика (Frida не вызывает хуки внутри хука) — для отладки есть `refreshBookTiles`.
* Наблюдение: при одновременном старте нескольких модов с `whenReady` игра один раз зависла (JS-поток замер, лог остановился на «шаг 1») — воспроизводилось ~в половине запусков без моего кода
  иконок, причину не выясняли.

## Мод «Проклятия и дары»

Включается в окне «Моды». После этого на экране «Исследование» (иконка ДНК) нажатие на **заголовок** открывает красный экран
«Проклятия и дары» — те же иконки исследований, но с недостатком. Нажатие на плитку повышает уровень (0–5, после максимума сброс).

* Правило **2 к 1**: уровень даёт +1% своей характеристики и −2% характеристики парного исследования.
* Пары **взаимно исключают** друг друга (выбрал одну — вторая сбрасывается): Интеллект ↔ Живучесть, Быстрый запуск ↔ Меткость,
  Сопротивляемость ↔ Ловкость, Ускорение ↔ Оживление.
* Эффекты применяются к герою в бою через подстановку в слоты `효과ID_NN` перед `AbilityStatApply` (см. «Свои эффекты»; для статических величин — `db: true`);
  исходный код — `modkit/src/mods/curses.ts`.
  Мод пользуется общими инструментами `uikit.ts` и хуком `onMainMenu` — по нему можно писать другие моды с собственными экранами.
* Проверено по экрану паузы: атака, получаемый урон, уклонение, шанс крита, регенерация, максимальное здоровье.
  Скорость движения и перезарядка записываются в поля, но экран паузы их не показывает — реальное действие в бою не проверено.
  Размер, длительность, мана, руны, предметы и сундуки (`AllyUnitVar_*`) записываются стабильно, но визуально подтверждён только радиус.
* Пока нет: стоимости уровней (очки исследования), пар «Рассеивание ↔ Концентрация», «Оживление ↔ Очистка маны»,
  «Благословение ↔ Удача», «Добыча ↔ Поиск» — для них не найдено, где хранятся значения.
* Исследования разработчика устроены так: строки таблицы `Ability` (ID 261–282) с эффектами, уровни в `Z_Database.Array_Research_Level`,
  очки в `Game_ResearchPoint`. Эффекты исследований игра складывает в статические `Z_Database.AllyUnitVar_*` (проценты, каналы U — бонус, D — штраф)
  внутри `V_Ability_Manager.AbilityStatApply`, который пересчитывает их с нуля при старте боя и повышении уровня.

## Ограничения

**Установка и платформа**
* Игра ставится **пересобранной и переподписанной** — обновления из Google Play на неё не лягут, вход через Google Play Games,
  облачные сохранения, покупки и реклама могут не работать. Оригинал надо удалять (локальные сохранения теряются).
* Работает только на **arm64-телефоне**. В эмуляторе Android Studio (x86_64 с трансляцией ARM) Frida не работает: игра падает.
  На ПК через другие эмуляторы я не проверял; нативной ПК-версии из этих файлов не получить.
* Используется **frida-gadget 16.7.19**. Gadget 17.19.0 на этом телефоне падает при старте. Java bridge Frida 16 тоже
  падает — поэтому меню сделано на Unity UI, а не на Android-виджетах. npm-пакет `frida-java-bridge` с Frida 16 несовместим.
* Файлы в `Android/data/...` создаёт приложение; `adb push` поверх существующего файла не работает (`push.ps1` обходит это
  через `/data/local/tmp`).

**Что доступно из кода**
* Unity собран со *stripping*: многие методы вырезаны (например `Canvas.set_renderMode`, `RectTransform.SetInsetAndSizeFromParentEdge`).
  Вызывать можно только то, что есть в `dump.cs`. Хорошая привычка — искать метод в дампе до написания кода.
* Код, который трогает Unity-объекты (создание UI, `GameObject`), нужно выполнять на **главном потоке Unity**. Хук в `ui.ts`
  (`A_MainMenuInformation.Update`) — пример. Код из `setInterval`/`ctx.every` идёт в другом потоке: чтение и запись полей работает,
  создание Unity-объектов — нет.
* Иконка-ключ и окно «Моды» есть **только на главном экране**. В бою меню нет, но включённые моды продолжают работать.
* Иконка гаечного ключа нарисована программно (`Sprite.Create` вырезан), положение подогнано под экран 720×1640 и под текущую раскладку главного меню.
* `ctx.replace` не позволяет вызвать оригинальный метод (рекурсия через перехват).

**Правка данных**
* Править можно значения, тексты и набор эффектов у существующих записей. «Новая» запись — это комбинация **уже существующих**
  эффектов. Совершенно новое поведение (эффект, которого игра не знает) требует кода: хука на метод, который обрабатывает эффекты.
* Иконки хранятся в массивах спрайтов по ID (`SpriteList_*Portrait`). Новая запись получает иконку образца, из которого скопирована.
* **Не проверено в игре:** выпадает ли новый артефакт из сундука/выбора; как ведёт себя новая запись в `MagicCom`, `Synergy`
  (там, скорее всего, привязка идёт к конкретным ID в коде). Энциклопедия показывает фиксированную сетку, новый артефакт в ней не появился.
* Ультимейты: отдельной таблицы я не нашёл. По названиям колонок они, вероятно, лежат в `Class` / `Ability` (`특수패시브`),
  но это не проверено.
* Таблицы могут перечитываться игрой при смене сцены — если правки «слетают», их нужно накладывать повторно.
* В игре есть Anti-Cheat Toolkit (ACTk). Реакцию на моды я не видел, но для онлайн-функций (рейтинги, облако) риск остаётся. Для одиночной игры это не важно.

**Проверено и не проверено**
* Проверено на телефоне: установка патченого APK, запуск, дамп классов и таблиц, включение всех четырёх кодовых модов без ошибок и бой с
  ними, меню MODS (открытие, переключатели, шаговые настройки, сохранение в `config.json`), правка и добавление записи в `Ability`.
* Не измерялось: точный игровой эффект (например реальный ×2 к скорости, убийство одним попаданием на боссах), перезапуск после
  выключения всех модов в бою, поведение при долгой игре.
